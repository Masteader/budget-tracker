# Final review: backend and database

Base `4ab1534` (origin main), reviewed head `952098d` (`audit/claude-comprehensive-review`), 2026-10-20.
Scope: `git diff 4ab1534...HEAD -- ai_service supabase`, excluding `ai_service/static` and `_landing_impl.py`.
This was a fresh-eyes pass after many agents' work was merged. It looked for cross-module drift, wrong column, RPC and error contracts, authorization gaps, Nafaqah, permission and settlement interactions, cycle consistency, money types and dead code.

## How findings were verified

- **Real schema.** The column lists of `public.transactions`, `users`, `households`, `budgets` and other tables were read from the local rebuild (PG16, all migrations). `live_db_preflight.md` (D13 and MOB-03) says live has the same columns: there is **no `paid_by`, `beneficiary` or `notes` column** on `transactions`.
- **Schema-aware fake.** The test fake (`ai_service/tests/fakes.py`) can now enforce a table's real column list (`client.schemas[...]`), rejecting unknown columns and returning only the selected ones, the way PostgREST does. The new tests in `ai_service/tests/test_final_review_backend.py` run with the live `transactions` columns. Before this, the fake accepted any column, so the suites stayed green while these code paths failed in production.
- **Database-side proof.** `supabase/tests/21_review_backend_contracts.sql` runs on a fresh local rebuild. It proves the `financial_role` fix and the settlement-row contract. The old settlement payload fails there with 42703 and 23503.
- Every fix was test-first: each new test was run and seen to fail before the code change.

## Remaining caveats

- Settlement payments are still stored as `transactions` rows (`is_settlement = true`, category NULL). The Python aggregations now skip them. Client-side totals that sum every transaction (the Flutter feed and PDF statement) still list them; they are clearly labelled "Settlement Reimbursement".
- The fixes to the settlement engines read who paid from the `PaidBy:` audit tags. Rows with no tag and no creator (the 14 legacy live rows) are not attributed in roommate debts. That is deliberate: guessing would assign money to the wrong person.
