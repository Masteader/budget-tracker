## 3. Auth redirects

**Logins that exist:** email and password (`signInWithPassword`, `signUp`), and an email link or code for recovery (`resetPasswordForEmail`, with `signInWithOtp` as a fallback). There is no social or OAuth login.

**How the manifest's schemes and hosts are used:**

| Target | Used by | Goes through the Supabase allow-list? |
|---|---|---|
| `budgettracker://reset-password` | `authResetRedirectUrl` default, password reset; also the `ai_service/landing_page.py` hand-off | Yes, as `redirectTo` (the web hand-off itself doesn't) |
| `FASTAPI_BASE_URL` | `authRedirectUrl` default, sign-up confirmation | Yes, as `emailRedirectTo` |
| `budgettracker://login` | `ai_service/landing_page.py`, open-app button | No, the web page links to it |
| `budgettracker://auth-callback` | No code in this repo | Kept for Android parity |
| `io.supabase.budgettracker` | No code in this repo | Kept for Android parity |

`AUTH_REDIRECT_URL` and `AUTH_RESET_REDIRECT_URL` can override these at build time, so a real build's `--dart-define` values matter `[verify]`.

**iOS has no host filter.** Android accepts only three hosts under `budgettracker`. `CFBundleURLSchemes` matches on scheme alone, so iOS delivers every `budgettracker://` link to the app.

**Why deep linking is off.** app_links requires `FlutterDeepLinkingEnabled=false`, confirmed at the locked version 7.2.1:

- The published 7.2.1 package sets it in `example/ios/Runner/Info.plist:41-42`. Its pub cache copy has no `doc/` folder.
- Its [7.x iOS guide](https://github.com/llfbandit/app_links/blob/7.2.0/doc/README_ios_7.md) has a "Disable default Flutter deep linking" step, required since Flutter 3.24. This is read at tag `7.2.0`, because the repository has no `7.2.1` tag.

Otherwise Flutter also pushes the URL as a named route. `MaterialApp` here has only `home`, so a route with the auth code in it is an unknown route. app_links 7.2.1 handles scene callbacks, which the generated `SceneDelegate` forwards.

Android has no matching `flutter_deeplinking_enabled=false` in its manifest. That may be a live bug on Android `[verify]`, and it is out of scope here.

### Security findings for review

1. **Pre-existing: a crafted link can set a session (found by reading code, not exploited).** With PKCE on, `getSessionFromUrl` in gotrue 2.27.2 throws only if the URL has neither `code` nor `access_token`. A link such as `budgettracker://login?access_token=...&refresh_token=...&expires_in=...&token_type=bearer` carrying valid tokens for an attacker's account gets saved as the session. A victim who taps it could enter financial data into the attacker's account. This already applies on Android, and iOS widens it to every host. A likely fix is `FlutterAuthClientOptions.detectSessionInUriPredicate`, accepting only the expected scheme, host and `code`. It touches auth, so it needs its own sensitive task, and it must first check the `hash` hand-off in `landing_page.py`. **Not changed here.**
2. **Pre-existing: a crafted link can reset the signed-in UI (found by reading code, not run).** A link such as `budgettracker://anything?error=x` reaches `getSessionFromUrl`, which throws. `_handleDeeplink` calls `notifyException`, which puts an error on the auth stream, so `AuthGate` sees no session and shows login to a signed-in user. `_handleSignedOut` (`main.dart:204-225`) then resets the providers and cancels reminders, but `signOut` is never called, so the session stays stored. Android limits this to its three `budgettracker` hosts, plus any host under `io.supabase.budgettracker`. iOS accepts any host on both schemes. **Not changed here.**
3. **Scheme claiming.** Another app can register the same custom scheme, and iOS doesn't guarantee which one opens. PKCE (default in `supabase` 2.16.1, not overridden in `main.dart`) protects the `code`, because the verifier stays on the device. Universal Links on an owned domain would close this, and are an option for later.

Findings 1 and 2 await the owner's decision on a separate task.

## 4. Steps on a Mac

You need Xcode 26 or later, which Apple has required for uploads since April 28, 2026 ([source](https://developer.apple.com/news/upcoming-requirements/)), CocoaPods, and Flutter 3.44 or later (`pubspec.lock` requires it; this project was generated with 3.47.8). Use a physical iPhone for camera, speech and notification checks.

```bash
cd flutter_app
flutter pub get --enforce-lockfile      # never `flutter create`: it upgrades pubspec.lock
cd ios && pod install && cd ..

# First real test: compile without signing.
flutter build ios --debug --no-codesign --dart-define-from-file=dart_defines.json
```

`dart_defines.json` is git-ignored; copy it from `dart_defines.example.json`. Only the publishable key belongs in it, never a secret or service-role key.

**Signing**

1. `open ios/Runner.xcworkspace` (the workspace, not the project).
2. Select Runner > Signing & Capabilities, choose the Team, and keep automatic signing on.
3. Confirm the Bundle Identifier is `com.budgettracker`.

A free Apple account can run on your own device, with profiles expiring after 7 days ([source](https://developer.apple.com/support/compare-memberships/)). No capabilities or entitlements were added: `flutter_secure_storage`'s README asks for Keychain Sharing only on macOS `[verify]`.

**Release build**

```bash
flutter build ipa --obfuscate --split-debug-info=build/symbols --dart-define-from-file=dart_defines.json
```

Upload `build/ios/ipa/*.ipa` with Transporter or Xcode ([Flutter guide](https://docs.flutter.dev/deployment/ios)). Each upload needs a new build number, from `version` in `pubspec.yaml`. Release values must be `https://`.

**Commit afterwards:** `ios/Podfile.lock` (the root `.gitignore` has `*.lock`, with a negation for this one file), and the `project.pbxproj` and workspace changes from `pod install`, Flutter's migrations and your Team ID. `flutter_app/test/ios/ios_project_config_test.dart` should still pass after those changes.

## 5. Apple Developer Program

**Needed for TestFlight and the App Store.** App Store Connect comes with enrollment ([compare memberships](https://developer.apple.com/support/compare-memberships/)).

**Cost:** $99 USD per membership year, and prices may vary by region and appear in local currency during enrollment ([enroll](https://developer.apple.com/programs/enroll/)). **Spending this needs the owner's approval.**

**Individual or organization:** guideline 5.1.1(ix) says apps in regulated fields such as banking and financial services "should be submitted by a legal entity that provides the services, and not by an individual developer". Guideline 3.2.1(viii) says financial trading, investing or money management apps should come from the institution performing the service. Whether a household budgeting app that moves no real money falls under these is `[verify]`; decide before enrolling. Organizations need a D-U-N-S number, a legal entity (no trade names), and a working website on their own domain.

**Sign in with Apple is not required.** Guideline 4.8 applies only to apps using a third-party or social login for the primary account, and this app uses only its own email accounts. If Google, Facebook or similar login is added later, this changes.

**TestFlight** ([overview](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/)): up to 100 internal testers and 10,000 external. The first build for external testers goes through review. Builds expire after 90 days.

## 6. Plugin checklist

**Read this first: `permission_handler` under Swift Package Manager.** SwiftPM is on by default in Flutter 3.47.8, so a Mac build is a hybrid: plugins with a `Package.swift` build through SwiftPM, and `flutter_local_notifications`, which has none, builds through CocoaPods. `podhelper.rb` skips the rest, so **the Podfile's `PERMISSION_*` macros don't apply by default**. `permission_handler_apple` then derives them from `Info.plist`:

| Macro | Hybrid (default) | CocoaPods only (Podfile) |
|---|---|---|
| CAMERA, MICROPHONE, NOTIFICATIONS | 1 | 1 |
| SPEECH_RECOGNIZER, PHOTOS | 1, because their keys are in `Info.plist` for other plugins | 0 |
| All others | 0 | 0 |

The app only calls `Permission.camera`, `.microphone` and `.notification`. Both columns are safe, since every enabled group has its string. To get exactly the used set under SwiftPM, `launchctl setenv PERMISSION_SPEECH_RECOGNIZER 0` and the same for `PERMISSION_PHOTOS`. To force CocoaPods, run `flutter config --no-enable-swift-package-manager` on that machine.

**Trap:** a build started from Xcode.app can't find `Info.plist` under SwiftPM, so all these permissions compile out and report `denied`, with no visible warning. Use `flutter build`, or first run:

```bash
launchctl setenv PERMISSION_HANDLER_INFO_PLIST "$PWD/ios/Runner/Info.plist"
rm -rf ~/Library/Developer/Xcode/DerivedData
```

Check the result with the `swift package ... dump-package` command in that plugin's README. Clear DerivedData after any change to `Info.plist`.
