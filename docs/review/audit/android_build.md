# Android build verification

Date: 2026-10-20 · Branch: `audit/claude-comprehensive-review` (from `952098d`) · Related: [`flutter_logic.md`](flutter_logic.md) (MOB-02, MOB-18, MOB-19), [`MASTER_AUDIT_REPORT.md`](MASTER_AUDIT_REPORT.md) §4 item 8

Until now this audit had not built the Flutter app for Android, because the sandbox had no Android SDK. Since the last build, the branch has added native plugins (`flutter_secure_storage` 11, `share_plus` 13, `path_provider`) and changed the Android config: backups off, cleartext off, release signing from `key.properties`, minSdk 26. This document records the first real Android build of the branch.

## 3. Commands

All builds used obviously fake compile-time configuration. The values pass `validateClientConfig` (https in release; the key is not `sb_secret_`/service-role) and point nowhere real:

```bash
cd flutter_app
flutter pub get
DEFINES="--dart-define=SUPABASE_URL=https://example.invalid \
         --dart-define=SUPABASE_PUBLISHABLE_KEY=sb_publishable_FAKE_LOCAL_BUILD_ONLY \
         --dart-define=FASTAPI_BASE_URL=https://example.invalid"
flutter build apk --debug   $DEFINES
flutter build apk --release $DEFINES          # no android/key.properties
# throwaway upload key, created OUTSIDE the repo (scratch dir), 30-day validity:
#   keytool -genkeypair -keystore <scratch>/throwaway-upload.jks -storetype PKCS12 \
#           -alias upload -keyalg RSA -keysize 2048 -validity 30 ...
# temporary flutter_app/android/key.properties (git-ignored) pointing at it, then:
flutter build apk --release       $DEFINES
flutter build appbundle --release $DEFINES
# key.properties deleted afterwards; the keystore never entered the repo.
flutter analyze
flutter test
```

**Network note (sandbox only, not a project problem).** About 1 in 6 requests to `repo.maven.apache.org` got a random Cloudflare `HTTP 429` from this sandbox, in both curl and Gradle. Gradle makes hundreds of POM/JAR requests, so almost every cold build failed on one of them. The fix was to retry the unchanged `flutter build` command in a loop. Gradle caches each request that succeeded, so every retry got further: the first release build succeeded on its 8th attempt, and the signed APK and the AAB on their 1st. A developer machine or CI runner with normal Maven Central access needs none of this.

The cold debug build spent 431 s in Gradle, including the NDK, CMake and platform downloads. Warm release builds took 5–100 s.

## 4. Release APK inspection

Tools: `aapt2 dump badging` / `dump xmltree` / `dump resources`, `apksigner verify`, `zipalign -c -P 16`, `readelf -lW`, `dexdump`, and the R8 `mapping.txt`.

### 4.1 Identity and SDK levels

- Package `com.budgettracker`, versionCode 3, versionName 1.0.2 (from `pubspec.yaml` `1.0.2+3`).
- `minSdkVersion` 26, `targetSdkVersion` 36, `compileSdkVersion` 36.
- ABIs: `arm64-v8a`, `armeabi-v7a`, `x86_64`.

### 4.2 Permissions (merged manifest)

|---|---|
| `INTERNET`, `ACCESS_NETWORK_STATE` | app manifest |

**No SMS permission.** `READ_SMS`, `RECEIVE_SMS`, `SEND_SMS` and the rest are absent. The string `SMS` does not appear anywhere in the merged manifest (0 matches). This satisfies the zero-SMS-interception rule (`.agents/rules/04`). No storage, location, contacts, phone-state or `QUERY_ALL_PACKAGES` permission is merged in by any plugin.

### 4.3 Backup, cleartext, debuggability

|---|---|---|

| `android:dataExtractionRules` | `@xml/data_extraction_rules` (R8-shortened to `res/4j.xml`). Content checked in the APK: `<cloud-backup>` and `<device-transfer>` each exclude `root`, `file`, `database`, `sharedpref`, `external` | ✓ |

Exported components: only `MainActivity` (launcher) and AndroidX `ProfileInstallReceiver`. The receiver is guarded by `android.permission.DUMP`, which only the shell/system holds, and is standard. Every plugin provider, service and receiver (image_picker and share_plus `FileProvider`s, `SharePlusPendingIntent`, ML Kit, CameraX, datatransport) has `exported=false`.

### 4.4 Signing

- **Without `key.properties`:** signed with the Android debug certificate (`CN=Android Debug`, SHA-256 `14061bb8…b8e8`). This is the documented fallback in `android/app/build.gradle.kts`. Gradle logs `android/key.properties not found: release build is signed with the DEBUG key.`, but **`flutter build` hides that warning**, so the build looks like an ordinary success. Such an APK cannot be uploaded to Play or update a store install. See recommendation R1.
- **With the throwaway `key.properties`:** the APK verifies under APK Signature Scheme v2 with the upload certificate (`CN=Throwaway Local Build`). v1 is not needed at minSdk 26. The AAB verifies with `jarsigner` as signed by the same certificate. This proves the `signingConfigs.release` wiring works end to end.

### 4.5 Native code and plugins

- **`flutter_secure_storage` is present.** The debug dex contains `com.it_nomads.fluttersecurestorage.*` (plugin, storage, `ciphers.*`). In the release build R8 keeps and renames it: `FlutterSecureStoragePlugin -> b20`, `FlutterSecureStorage -> y10`, 21 `com.it_nomads` classes in `mapping.txt`. `GeneratedPluginRegistrant` references the plugin directly, so renaming is safe, and the method channel is looked up by string. Version 11.2.0 does its encryption with `javax.crypto` and the AndroidKeyStore (AES-GCM storage cipher, RSA-OAEP/AES key cipher). It declares `tink-android` but never references it, so R8 legitimately removes Tink from the release dex. No ProGuard rule is needed.
- **`share_plus`** is present (`SharePlusPlugin -> kz0`, `ShareFileProvider`, `SharePlusPendingIntent`).
- **`path_provider_android` 2.3.1** runs through `jni`: `com.github.dart_lang.jni.*` is kept unrenamed, and `libdartjni.so` ships for all three ABIs.
- Release native libraries per ABI: `libapp.so` (AOT), `libflutter.so`, `libdartjni.so`, `libbarhopper_v3.so` (ML Kit barcode, `mobile_scanner`), `libimage_processing_util_jni.so`, `libsurface_util_jni.so` (CameraX), `libdatastore_shared_counter.so`.
- **16 KB pages:** `zipalign -c -P 16` passes. Every 64-bit `.so` has LOAD alignment of at least `0x4000`, and `libapp.so`/`libflutter.so` have `0x10000`. This meets Play's 16 KB page-size requirement for targetSdk 35+.
- The debug APK also carries `libsqlite3.so`, from the dev dependency `sqflite_common_ffi` → `sqlite3` native-assets hook. The release build correctly omits it, because the app uses the platform SQLite through `sqflite_android`.

Captured with `./gradlew --offline --warning-mode all :app:help`. None of these fails the build.

- `WARNING: The option setting 'android.newDsl=false' is deprecated` and `... 'android.builtInKotlin=false' is deprecated`. ## 6. Emulator smoke test

**Not run.** `/dev/kvm` does not exist in this sandbox. Current Android emulators need hardware acceleration for x86_64 system images and cannot run ARM images on an x86 host, so a headless boot is not possible here. The release APK is fine for a device or emulator test elsewhere. With the fake defines it should start and show the login screen. The config validator passes (https URLs, non-privileged key), and network calls then fail against `example.invalid`. To see the missing-config screen instead, build without `--dart-define`s.

Suggested follow-up on a machine with KVM or a device:

```bash
flutter build apk --debug $DEFINES
adb install -r build/app/outputs/flutter-apk/app-debug.apk
adb shell am start -n com.budgettracker/.MainActivity
adb logcat -d | grep -E "FATAL|AndroidRuntime|flutter"
```

## 7. Recommendations

- **R1 (Medium). Make a store build fail without the upload key.** The debug-key fallback is deliberate for local `flutter run --release`. But `flutter build apk|appbundle --release` succeeds silently without `key.properties`, because the Gradle warning is not shown, so a debug-signed artifact can reach a release pipeline unnoticed. Options:
  - add a CI step that runs `apksigner verify --print-certs` and rejects `CN=Android Debug`;
  - in `build.gradle.kts`, throw when the task graph contains `bundleRelease` and `key.properties` is missing, keeping the fallback for `assembleRelease`/`flutter run`.

  This audit did not change the signing behaviour, because it is a release-process decision for the owner (MOB-18).
- **R2 (Low). Declare the microphone optional.** `RECORD_AUDIO` makes Play infer `uses-feature android.hardware.microphone` as *required*, which hides the app from devices without a microphone. Voice entry is optional, so `<uses-feature android:name="android.hardware.microphone" android:required="false" />` in `AndroidManifest.xml` would widen device reach. The camera is already `required=false`.
- **R3 (Low). Build the release APK/AAB in CI** with the same fake `--dart-define`s, so a plugin or AGP bump cannot silently break the Android build again. The toolchain in §2 is enough.
