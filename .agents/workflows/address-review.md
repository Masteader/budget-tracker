# Workflow: Address Opus Audit Findings & Re-Verify

1. **Read the Audit Feedback**
   - Read `docs/review/AUDIT_FEEDBACK.md` (generated by `scripts/claude_auditor.py --mode review`).
   - If the user pasted feedback directly in the prompt, use that instead.

2. **Parse Findings & Build an Action Checklist**
   - Extract every `CRITICAL`, `HIGH`, `MEDIUM`, and `LOW` / `NIT` item from the feedback.
   - Prioritize: CRITICAL first, then HIGH, then MEDIUM.

3. **Implement Fixes Following TDD (Rule 05)**
   - For each finding, add or update the corresponding unit/widget/pytest test first.
   - Implement the code fix cleanly without breaking Rules 01–05.
   - Opus writes professional, senior-level feedback — follow its instructions precisely.

4. **Run Full Verification Gate**
   - Run `cd flutter_app && flutter analyze`
   - Run `cd flutter_app && flutter test`
   - Run `cd ai_service && .venv\Scripts\pytest -v`

5. **Re-Trigger the Opus Review**
   - Run: `python scripts/claude_auditor.py --mode review --verbose`
   - This sends the updated file contents to Claude Opus for re-evaluation.
   - For batch mode: `python scripts/claude_auditor.py --mode review --batch --verbose`

6. **Repeat Until APPROVED**
   - If `AUDIT VERDICT: REVISE` again, go back to Step 1.
   - If `AUDIT VERDICT: APPROVED`, inform the user and wait for sign-off.

7. **Commit, Push, and Notify User**
   - Commit fixes: `git commit -m "fix(review): address Opus audit findings"`
   - Push to the active PR branch: `git push origin HEAD`
   - Inform the user: "Claude Opus 5.5 has approved all changes. Ready for your final sign-off to merge to main."
